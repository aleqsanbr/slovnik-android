## 1. Что это вообще такое

Есть две части, и важно не путать, где что живёт.

1. **«Словник» — артефакт на claude.ai**: https://claude.ai/artifact/L2DuyM3QrRJHowUuoqp6mh
   Это и есть приложение: одна HTML-страница (разметка, CSS и JS в одном файле) с карточками для английских слов из книг. В ней интервальные повторения EN→RU / RU→EN / вперемешку, наборы, разбор списков слов через Claude, озвучка, звуки, серия занятий, настройки напоминаний. Данные хранятся в облачной базе артефакта (capability `db`), а автоперевод идёт через capability `sample` (вызов Claude от имени пользователя). **Исходник страницы — сам артефакт, а не этот репозиторий.**

2. **Этот репозиторий — нативная Android-оболочка** (Java, без AndroidX и без Kotlin). Она открывает артефакт в WebView и добавляет то, чего страница сама не умеет: работу без сети, системные цвета панелей, скрытие шапки claude.ai, озвучку через Android TTS, тактильный отклик, сохранение файлов в «Загрузки», напоминания, виджет, заставку и отладочный лог.

Страница обязана работать и **без** приложения, в обычном браузере. Всё нативное подключается опционально, через мост `window.SlovnikNative` (см. §4).

### Копия страницы в репозитории

`app/src/main/assets/slovnik.html` — копия страницы артефакта, вшитая в APK. Это запасной вариант для офлайн-режима, если приложение ещё ни разу не открывалось с сетью или сохранённая копия сломана. Обычно офлайн открывается копия, которую онлайн-страница сама отдаёт приложению при каждом открытии (`savePage`, §5.3).

**Когда меняешь страницу артефакта, обновляй и `assets/slovnik.html`**, чтобы копии не расходились. Файл в том же формате, в каком публикуется артефакт: без `<!doctype>`, `<html>`, `<head>`, `<body>`. Обёртку добавляет `MainActivity.loadOffline()`.

## 3. Архитектура приложения

### 3.1 Онлайн и офлайн

`MainActivity.open(tab)` при каждом запуске решает заново, состояние WebView не восстанавливается:

- Если Android говорит, что сети нет (`isNetworkOk()` == false), сразу открывается офлайн.
- Иначе грузится онлайн-страница **и параллельно** идёт проба `probeClaude()`: HEAD-запрос к `https://claude.ai/favicon.ico` с таймаутом 4 с. Если ответа нет, а страница ещё не стартовала, открывается офлайн.
- Сторож `onlineWatch`: если онлайн-страница не сообщила `pageAlive`, через 6 с и далее каждые 5 с проверяется сеть; при её отсутствии или после 4 проверок (~20 с) открывается офлайн. Страницы входа в Claude сторож не трогает.
- `onReceivedError` для основного фрейма → офлайн.
- `onResume` в офлайне делает пробу и возвращает онлайн, только если claude.ai реально ответил.
- `offlineWatch`: если сохранённая офлайн-копия не стартовала за 4 с, открывается копия из `assets`.

> **Ловушка (уже было):** с включённым VPN Android считает сеть подтверждённой даже без интернета. Поэтому `isNetworkOk()` недостаточно: решение «онлайн» всегда подкрепляется пробой. Не убирай пробу.

Офлайн-копия грузится через `loadDataWithBaseURL("https://slovnik.local/index.html#tab", …)` с минимальной обёрткой `<!doctype html>…<body>`. `window.claude` там нет, есть только мост.

### 3.2 Онлайн-страница внутри claude.ai

- Внутри приложения открываются только путь артефакта (`ARTIFACT_PATH`) и страницы входа в Claude (`AUTH_PREFIXES`). Всё остальное уходит во внешний браузер: и навигации основного фрейма (`shouldOverrideUrlLoading`), и SPA-переходы claude.ai (`doUpdateVisitedHistory`). После входа приложение само возвращается в «Словник».
- **Шапка claude.ai прячется сдвигом WebView**: `MEASURE_JS` раз в ~0,7 с меряет `top` самого большого iframe (это высота шапки), WebView растягивается на эту высоту и сдвигается вверх (`applyHeaderShift`). Если на странице открыт диалог claude.ai (`role=dialog`), сдвиг снимается, чтобы диалог было видно.

> **Ловушка:** внедрить CSS в claude.ai нельзя: его CSP блокирует вставленные `<style>`. Поэтому сдвиг, а не стили.

- Вход в Claude внутри WebView: Google OAuth во встроенных браузерах заблокирован, работает вход по почте. Ссылку из письма открывают в обычном браузере, он показывает код, код вводят в приложении.

### 3.3 Цвета системных панелей

`sampleBars()` раз в ~0,7 с через `PixelCopy` читает два пикселя того, что реально нарисовано: фон слева на середине экрана → статус-бар, низ экрана → навигационная панель. Так панели совпадают с любой темой и цветом Material You, выбранными в «Словнике», без всякой связи со страницей. `targetSdk = 34` намеренно: на 35 Android принудительно включает edge-to-edge, и `setStatusBarColor` перестаёт работать.

### 3.4 Остальное в MainActivity

- **Заставка** (`showSplash` / `hideSplash`): круг в цвете иконки, внутри передний план иконки в масштабе 0,8, название и лоадер. Прячется по `pageAlive` (+450 мс) с колокольчиком (`playReadyChime`, синтез через `AudioTrack`, молчит в беззвучном и вибро-режиме) и тактильным откликом. Убирается сама через 12 с или на странице входа. У родительских слоёв `setClipChildren(false)`, иначе круг обрезается при масштабировании. Настройки звука и вибрации читаются из снимка словаря (`meta.sound`, `meta.haptics`).
- **TTS**: `android.speech.tts.TextToSpeech` с локалью en-US/en-GB, говорит системный движок. Для Android 11+ в манифесте нужен `<queries>` с `TTS_SERVICE`.
- **Кэш озвучки** (`TtsCache`): всё, что сказал движок, ещё и рендерится в WAV (`synthesizeToFile`) в `filesDir/tts/<sha1>.wav`. Попадание в кэш играет `MediaPlayer` мгновенно, без движка. Промах: движок говорит вживую (`QUEUE_FLUSH`), а после окончания фраза рендерится в файл. В начале подхода страница присылает слова (`ttsPrefetch`), они рендерятся по одной в фоне. Ключ = версия кэша + движок + голос + акцент + текст, поэтому смена голоса не подсовывает старые записи. Перед озвучкой к фразе без завершающего знака добавляется точка (`TtsCache.speakable`): нейронные голоса вроде Kokoro иначе дорисовывают в конце шипение «с»/«th». Если меняешь то, как фразы рендерятся, подними `CACHE_VERSION`: старые записи удалятся один раз при запуске. Лимит 150 МБ, вытесняются давно не игравшиеся (по `lastModified`, который обновляется при проигрывании). Очистка: кнопка в «Звук и озвучка» и пункт в отладочных действиях. Там же «Озвучить все слова»: страница отдаёт все слова (`ttsPrefetchAll`), недостающие рендерятся по очереди как «задание» с прогрессом (`ttsProgress` → `{total, done, failed, active}`, страница опрашивает раз в 0,7 с, пока открыта вкладка), `ttsPrefetchCancel` останавливает. Живая озвучка прерывает рендер, прерванная фраза возвращается в очередь и не считается неудачей. Кэшировать можно **только в нативке**: Web Speech в браузере звук наружу не отдаёт.
- **Вибрация**: `performHapticFeedback` (CLOCK_TICK / CONFIRM / REJECT), учитывает системную настройку и не требует разрешения.
- **Сохранение файлов**: `saveFile` пишет в «Загрузки» через `MediaStore.Downloads`. Скачивание blob-ссылок из WebView не работает, поэтому экспорт JSON в приложении идёт через мост.
- **Без растягивания при прокрутке**: `setOverScrollMode(OVER_SCROLL_NEVER)` + `overscroll-behavior:none` в странице.
- **Лог**: двойная встряска телефона открывает окно с логом (буфер на 500 строк, `MainActivity.log`). Наверху версия, режим, сеть (wifi/мобильная/VPN, подтверждена ли), размеры копий. Кнопки: «Скопировать», «Действия» (онлайн, офлайн-копия, тесты всех уведомлений, показать расписание, очистить кэш озвучки), «Закрыть». В лог пишутся загрузки, ошибки, сообщения консоли уровня error/warning (в том числе из iframe), события моста, решения о режиме, напоминания. **При любой проблеме на устройстве первым делом просить лог.**

## 4. Мост `window.SlovnikNative`

`addJavascriptInterface(new Bridge(), "SlovnikNative")`. Объект виден во **всех** фреймах, в том числе в iframe артефакта на claude.ai, это проверено.

На странице всё вызывается через `nativeCall(name, ...args)`: тот проверяет, что метод существует, и глушит исключения. **Новые методы добавляй только так**, потому что у пользователя может стоять старая версия APK без них. Страница не должна ломаться ни без моста, ни со старым мостом.

| Метод | Что делает |
|---|---|
| `isApp()` | признак, что страница открыта в приложении |
| `isOffline()` | открыта офлайн-копия |
| `online()` | Android сообщает о подтверждённой сети (для кнопки «Сеть есть, синхронизировать») |
| `goOnline()` | открыть онлайн-версию |
| `pageAlive()` | страница стартовала: гасит сторожей, прячет заставку, один раз просит разрешение на уведомления |
| `accent()` | системный акцент Material You `#RRGGBB` (Android 12+) для цвета «системный» |
| `saveSnapshot(json)` | сохранить копию словаря `{meta, seed, words[]}` и перерисовать виджеты |
| `snapshot()` | прочитать копию (офлайн-режим) |
| `savePage(html)` | сохранить код страницы для офлайна (только если ≥ 5000 символов и изменился) |
| `pendingPut(id, wordJson\|"")` | офлайн-правка слова; пустая строка — удаление |
| `pendingMeta(json)` | офлайн-правка `meta` |
| `takePending()` / `clearPending()` / `pendingCount()` | онлайн-страница забирает офлайн-правки и правки из шторки/виджета |
| `practiceDays()` | дни, когда отвечали из шторки или виджета (JSON-массив `YYYY-MM-DD`), для серии |
| `notifSettings(json)` | настройки напоминаний изменились: сохранить, перепланировать, при включении спросить разрешение |
| `notifAllowed()` | можно ли показывать уведомления |
| `testNotification(kind)` | показать тестовое уведомление `daily`/`quiz`/`streak`/`weekly` |
| `speak(text, lang)` / `stopSpeaking()` / `ttsReady()` | озвучка (через кэш, §3.4) |
| `ttsPrefetch(jsonArray, lang)` | заранее отрендерить фразы в кэш (до 80 за раз) |
| `ttsCacheInfo()` / `ttsCacheClear()` | `{"files":N,"bytes":B}` / очистить кэш озвучки |
| `ttsPrefetchAll(jsonArray, lang)` / `ttsProgress()` / `ttsPrefetchCancel()` | «Озвучить все слова»: запустить (до 5000 фраз), прогресс `{total, done, failed, active}`, остановить |
| `haptic(kind)` | `tick` / `confirm` / `reject` |
| `saveFile(name, content)` | сохранить файл в «Загрузки», возвращает успех |
| `jsLog(msg)` | строка в нативный лог |

## 5. Данные и синхронизация

### 5.1 Облако (в странице)

- База артефакта (`db`), личное поддерево пользователя: документ `data/users/<uid>/profile` (это `meta`: наборы, настройки, `notif`, `days` и т. д.) и подколлекция `…/profile/words/<id>` (одно слово — один документ).
- Каждое изменение сначала попадает в **outbox** (`localStorage` ключ `slovnik.outbox`) и удаляется оттуда только после подтверждения облака, поэтому правки без сети не теряются. Подписки `onSnapshot` не перезаписывают «грязные» записи.

> **Ловушка (уже было):** объекты из снимков `db` **заморожены**. Всё, что берёшь из `snap.data()` и потом меняешь, сначала прогоняй через `structuredClone`. Иначе изменение молча падает с TypeError: так не создавались наборы.

### 5.2 Слово

```json
{ "id": "w…", "en": "…", "ru": "…", "note": "…", "context": "…", "set": "<id набора или ''>",
  "lv": { "en": 0, "ru": 0 }, "due": { "en": 0, "ru": 0 }, "ok": 0, "bad": 0, "added": 1729200000000 }
```

`lv.en` / `due.en` — направление EN→RU, `lv.ru` / `due.ru` — RU→EN. Уровни 0…6, у каждого направления свои.

### 5.3 Файлы приложения (`getFilesDir()`, под `Store.LOCK`)

- `snapshot.json` — копия словаря, которую онлайн-страница отдаёт через `saveSnapshot` (с задержкой ~1,2 с после изменений). Из неё строятся офлайн-режим, напоминания и виджет.
- `pending.json` — `{words: {id: word|null}, meta}`: изменения, сделанные офлайн, из шторки или из виджета. Онлайн-страница забирает их (`mergeNativePending`) при подключении к облаку и при возвращении в приложение, кладёт в outbox и очищает.
- `tts/*.wav` — кэш озвучки (§3.4).
- `page.html` — последний код страницы, присланный онлайн-версией (`savePage`). Страница собирает его из своих элементов (`title`, шрифты, свой `<style>` с `--f-card`, `.app`, `nav.nav`, `#modal`, свой `<script>`), а не из всего `body`: обёртка claude.ai может добавлять свои элементы.

SharedPreferences:
- `notif`: `settings` (JSON из страницы), `days` (дни ответов из шторки/виджета), `count`/`countDay` (лимит в день), `asked`/`askedDay` (какие слова уже были в шторке сегодня), `askedPermission`.
- `widget`: `word_<id>`, `open_<id>` (текущее слово и раскрыта ли карточка у каждого виджета).

### 5.4 Алгоритм оценки — держать одинаковым в двух местах

Оценка реализована дважды: в странице (`grade()` в JS) и в приложении (`Notifications.applyGrade()`, им пользуются шторка и виджет). **Меняешь одно — меняй и другое.**

- интервалы по уровню: 10 мин, 1 д, 3 д, 7 д, 14 д, 30 д, 60 д; максимум уровня 6;
- «Не помню»: уровень −2 (не ниже 0), снова через 10 мин, `bad++`;
- «С трудом» (только в странице): уровень тот же, через max(10 мин, интервал/2), `ok++`;
- «Помню»: уровень +1, через интервал нового уровня, `ok++`.

## 6. Напоминания (`Notifications.java`)

Строятся из `snapshot.json`, поэтому работают без сети. Типы:

- `daily` — в выбранное время (по умолчанию 19:00), если есть слова со сроком: «N слов ждут повторения. Например: как перевести «…»?»;
- `quiz` — 0–3 в день (по умолчанию 2), слоты равномерно между концом тихих часов +2 ч и временем `daily` −1 ч: слово в шторке → «Показать перевод» → «Не помню»/«Помню» (`applyGrade`);
- `streak` — около 21:00, если серия ≥ 2 дней, а сегодня занятий не было;
- `weekly` — воскресенье 12:00: слова без перевода.

Правила (`onAlarm`): не в тихие часы (по умолчанию 22:00–9:00), не больше 3 в день, ничего, если сегодня уже занимался (`meta.days` ∪ дни из шторки/виджета), одно слово в шторке не чаще раза в день.

Расписание: `AlarmManager.setAndAllowWhileIdle` (неточные будильники, разрешение не нужно). `scheduleAll()` вызывается при запуске, после каждого срабатывания, при смене настроек, после выдачи разрешения и в `BootReceiver`. Настройки берутся из prefs `settings`, а если их нет, то из `meta.notif` снимка. На Android 13+ нужно разрешение `POST_NOTIFICATIONS`: просим один раз автоматически после `pageAlive` и повторно при включении напоминаний или тестах.

Тесты: в отладочном окне («Действия») и в настройках напоминаний на странице. Тест показывает уведомление сразу, игнорируя время, лимиты и условия, но берёт настоящие слова (или пример, если подходящих нет).

## 7. Виджет (`Widget.java`, `layout/widget.xml`)

Шапка: огонёк серии (акцентный, если сегодня занимался) и число слов к повтору, нажатие открывает «Повтор». Карточка: слово со сроком, нажатие раскрывает перевод и заметку, кнопки «Не помню»/«Помню» → `applyGrade` → следующее слово. Обновляется раз в 30 мин, после `saveSnapshot` и после оценок. Цвета виджета — ресурсы `widget_*` в `values*/colors.xml`. В разметке можно использовать только то, что поддерживает `RemoteViews`.

## 8. Версии и релизы

- Версия — в файле **`VERSION`** (семантическая, `MAJOR.MINOR.PATCH`). Это `versionName`.
  - **PATCH** (`1.2.0 → 1.2.1`) — исправления без новых возможностей;
  - **MINOR** (`1.2.1 → 1.3.0`) — новые возможности;
  - **MAJOR** (`1.x → 2.0.0`) — крупные несовместимые изменения (смена ключа подписи, формата данных и т. п.).
- `versionCode` = `GITHUB_RUN_NUMBER`, он всегда растёт, поэтому любая сборка ставится поверх предыдущей.
- **Релиз в GitHub создаётся только если тега `v$VERSION` ещё нет.** Значит, чтобы выпустить версию, подними `VERSION` в том же коммите (или в последнем из пачки). Пуш без смены версии просто соберётся для проверки: APK в артефактах запуска, в Releases ничего не появится.
- Заметки к релизу — список заголовков коммитов с прошлого тега, коммиты с `[skip ci]` выкидываются. Поэтому заголовки коммитов пишутся по-русски и по-человечески: они попадают в заметки.
- Если меняется только документация или страница артефакта без влияния на APK, добавь в сообщение коммита `[skip ci]`.
- Обновления у пользователя приходят через Obtainium из Releases, тег `vX.Y.Z` должен расти по semver.

Чек-лист изменения приложения:
1. Правки кода и ресурсов.
2. Если менялась страница артефакта — опубликовать её и скопировать в `assets/slovnik.html`.
3. Поднять `VERSION` по правилам выше (исправление → patch, возможность → minor).
4. При необходимости обновить README (список возможностей) и этот файл.
5. Коммит, пуш, дождаться тега `vX.Y.Z` (`git ls-remote --tags origin`).

## 9. Сборка и подпись

- CI: `.github/workflows/build.yml`, ubuntu-latest, JDK 17, Gradle 8.14.3 через `gradle/actions/setup-gradle` (**gradle wrapper в репозитории нет**), AGP 8.7.3, `compileSdk 35`, `targetSdk 34` (§3.3), `minSdk 29`. Lint при релизной сборке выключен.
- Подпись: ключ берётся из секрета **`KEYSTORE_B64`** (base64 файла `release.jks`), алиас `slovnik`, пароли в `app/build.gradle`. Сам ключ в репозиторий **не коммитить никогда** (`keystore/` и `*.jks` в `.gitignore`; когда-то ключ уже вычищали из истории). Смена ключа заставит пользователя переустановить приложение и заново войти в Claude — это MAJOR и только по согласованию.
- Локально: Android SDK + Gradle 8.9+, ключ в `keystore/release.jks`, команда `gradle assembleRelease`.
- Если в окружении агента нет Android SDK (dl.google.com и maven.google.com часто закрыты), собрать локально нельзя. Тогда:
  - **компилируй Java против настоящего `android.jar`**: его можно взять с GitHub (`curl -L -o android-34.jar https://raw.githubusercontent.com/Sable/android-platforms/master/android-34/android.jar`), сгенерировать минимальный `R.java` из ссылок `R.<тип>.<имя>` в коде и выполнить `javac -source 17 -target 17 -cp android-34.jar -d out R.java app/src/main/java/app/slovnik/*.java`. Это ловит почти все ошибки, на которых падает CI (так нашлась перекрытая локальной переменной `bg` ссылка на поле в `onCreate`);
  - проверяй XML (`python3 -c "import xml.dom.minidom …"`);
  - пользуйся только API, доступными на `minSdk 29`, остальное оборачивай в `Build.VERSION.SDK_INT >= …`;
  - результат CI виден по появлению тега/релиза. Статус запусков и длительность шагов отдаёт публичный API (`api.github.com/repos/aleqsanbr/slovnik-android/actions/runs`), а сами логи — нет (хранилище логов из окружения агента обычно закрыто). Если сборка упала, сначала скомпилируй локально, как описано выше; если не воспроизводится, попроси лог из вкладки Actions у владельца.
- Страницу удобно проверять в headless Chromium (Playwright), подставив заглушку `window.SlovnikNative` с нужными методами: так проверялись офлайн-режим, перемещение слов, экспорт, напоминания и серия.

## 11. Ограничения артефакта (страницы), которые важно помнить

- Страница работает в песочнице claude.ai: service worker, `alert/confirm/prompt`, `window.print`, прямые скачивания и большинство device API там недоступны. Нужное делается через capabilities (`db`, `sample`, `downloads`, `user`) или через мост приложения.
- Внешние скрипты — только с разрешённых CDN, шрифты — только Google Fonts.
- Хэш ссылки (`#add`, `#review`, `#words`, `#more`) доходит до страницы и открывает нужную вкладку; приложение использует это для ярлыков и уведомлений.
- Оформление: токены цветов строятся из одного seed-цвета в OKLCH (Material You), светлая и тёмная темы; цвет «системный» = акцент из `SlovnikNative.accent()` или CSS `AccentColor`.
